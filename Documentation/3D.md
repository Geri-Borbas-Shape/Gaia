# 3D star map

The iOS 27 app opens in **3D Map**. Drag to orbit, pinch to zoom and tap a visible star to select it. Its circle, name and plain **Star Data** button follow the star; tap **Star Data** to open its measurements. **Catalogue** keeps the searchable 8 pc list. The map uses the full 51,983-source, 50 pc sample.

## Appearance

- Marker radii follow Gaia GSP-Phot radii where available. Radii share an adaptive display scale, with a 24-point diameter cap to keep large markers from covering the map.
- Missing radii use a rough photometric estimate: absolute G luminosity relative to the Sun, corrected by a blackbody surface-brightness ratio at 673 nm. This is not a bolometric fit. Missing temperature or magnitude falls back to one solar radius.
- Colour smoothly follows effective temperature. A coarse BP−RP lookup supplies a display temperature when Gaia has none; unknown colour is neutral grey. The detail screen labels inferred radii and the approximate temperature class.
- Both camera modes choose up to 500 on-screen stars by apparent size (radius divided by camera depth). Smaller stars are omitted first. A shared scale keeps the smallest chosen marker at least 1.5–4.8 points wide, depending on Marker size. Cores, halos and hit testing use the same chosen indices.
- A custom Metal shader draws each core and a slight halo on a camera-facing billboard. Apparent sizes are exaggerated, not true angular diameters.

## Live glow controls

**Map Controls** opens with three glow sliders above the camera controls. The map keeps rendering behind the half-height sheet, and scrolling the controls keeps the preview visible.

- **Glow size** scales only the halo from 0.25× to 4×; 1× keeps the original size.
- **Glow intensity** sets peak brightness from 0% to 100%; 0% turns the glow off. The default is 16%.
- **Glow bias** changes the falloff from 0.25 to 4. Values below 1 spread the glow; values above 1 concentrate it. The default is 1.

**Reset glow** restores those defaults without moving the camera. **Reset view** restores all map settings. Values last for the current app session.

## Shader iteration

`Resources/StarGlow.metal` is the dedicated place to change the glow. `starBillboardGeometry` orients core quads and collapses invisible ones; `starCoreSurface` controls the opaque core and limb darkening. `starGlowVertex` places the halo billboards, and `starGlowFragment` controls their strength and falloff. At the default size, the halo extends to three stellar radii. `StarGlowSettings` supplies live uniforms: size scales the billboard, while intensity multiplies `pow(profile, bias)`. Bias preserves peak intensity and never changes star cores or visibility thresholds.

`StarSceneRenderer` renders the RealityKit cores and grid to a texture first. `StarGlowPass` then draws every halo over that completed image, with no depth attachment. Each billboard uses screen blending: `source + destination × (1 − source)`. Halos overlap the cores and each other without darkening, cutting holes or depending on draw order. Opaque cores discard fragments outside their circle, so partially transparent edges cannot write depth and obscure stars behind them.

`StarVisibility` uses a bounded heap to select the largest apparent stars when the camera, viewport or marker size changes. `StarBillboardField` updates only the chosen mesh indices, and `StarGlowPass` copies the same indices into each Metal command buffer. The catalogue vertex and instance data stay static. Billboarding and glow shading run on the GPU; no per-star entities are created. A shared Metal event orders the scene and glow queues before presentation.

Xcode compiles the package's Metal resource into its bundle. `makeDefaultLibrary(bundle: .module)` loads it. Install the matching Xcode Metal component if needed:

```bash
xcodebuild -downloadComponent MetalToolchain
```

[Apple's custom-material documentation](https://developer.apple.com/documentation/realitykit/modifying-realitykit-rendering-using-custom-materials) describes the shader interface.

## Camera and Galactic context

**Sun** starts outside the 50 pc sample, looking toward its centre. **Milky Way** moves to the Galactic overview. Field of view, marker exaggeration, orbit buttons and reset remain available. The Milky Way wireframe can be shown or hidden in either focus mode; selecting the Sun does not remove it. Both switches change only the camera. Stars remain visible at Galactic scale as a compact, overlapping group near the Sun; the catalogue still covers only 50 pc, not the whole galaxy. The shown count is the number of rendered catalogue entries, not separately resolved dots.

If a requested zoom or orbit would leave fewer than 100 catalogue stars in frame, the camera backs away just enough to retain them. This bounds the displayed sample to 100–500 without moving stars away from their real coordinates.

Selection stays with the chosen star as the camera moves, and hides when that star leaves the visible sample. Tapping empty space or Reset view clears selection. Closing Star Data returns to the selected star. The circle and name do not intercept gestures; the nearby text-only button opens the sheet.

The thin/thick disks are schematic: radius 13,400 pc and heights 335/2,600 pc. Galactic centre is `[8178, -20.8, 0]`. Galactic coordinates map to `[x, z, -y]`, with one scene unit per parsec and Y north. Positions stay Sun-centred for precision.

The scene retains the Stars prototype's camera, gestures and wireframe arrangement. Rendering uses `RealityRenderer` in an `MTKView`, without camera access. Updates pause when the tab is hidden, the app is inactive or star details are open. Reduce Motion skips focus interpolation. The package's model, projection and Metal glow tests also run on macOS.

## Validation

Package tests cover catalogue integrity, coordinate directions, radius and colour fallbacks, smooth colour transitions, size ratios, the draw budget and camera framing at extreme zoom and field of view. GPU tests check the actual glow pipeline's screen equation, draw-order independence, preserved alpha, invisible-star culling, exact draw-list selection and adjustable falloff. Simulator tests cover controls in both focus modes, orbit/pinch, live selection tracking, second-tap Star Data and catalogue details. The glow test compares the exposed map's brightness with the sheet still open, then verifies reset. Screenshots and native GitHub video attachments accompany the PR.
