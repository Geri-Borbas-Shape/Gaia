# 3D star map

The iOS app opens in a **3D Map** tab. **Catalogue** retains the searchable list and detail navigation.

## Interaction

- Drag to orbit the current centre. Pinch to change camera distance.
- Switch between **Sun** (the nearby 10 pc catalogue) and **Milky Way** (Galactic context). Recentering animates unless Reduce Motion is enabled.
- **Map controls** adjusts vertical field of view (10–80°), marker size, constant screen size, and the Milky Way wireframe. Direction buttons provide an alternative to dragging.
- **Reset view** restores the initial Sun-centred camera and default controls.
- Tap near a star to open its existing Gaia detail screen. The yellow marker represents the Sun, which is not a Gaia catalogue source.

Marker sizes are exaggerated and do not represent stellar radii. The 315 sources overlap around the Sun at Galactic scale; return to **Sun** to inspect individual stars. The Milky Way cylinders are schematic context, not a fitted Galactic model.

## Adaptation from Stars

The source project is `~/Projects/iOS/Prototype/Stars/Stars`.

| Stars implementation | Gaia adaptation |
|---|---|
| `Galaxy/GalaxyView.swift`, `GalaxyViewModel.swift` | RealityKit entity hierarchy, perspective camera, orbiting and animated recentering in `StarMapScene` |
| `Galaxy/ControlsView.swift` | Focus picker, field-of-view and sphere-size controls in `StarMapScreen` and `StarMapControls` |
| `Extensions/Entity+Extensions.swift` | Shared star sphere mesh, Sun marker, thin/thick disk wireframes |
| `PixelPerfectEntity/PixelPerfectEntity.swift` | Screen-size formula in `StarMapProjection`, updated each scene frame using camera-space depth and the actual viewport height |
| `Data/CoordinateConverters.swift` | Galactic spherical-to-Cartesian conversion using Gaia's existing longitude/latitude; no second catalogue or ICRS conversion is needed |

Gaia requires iOS 27 and Xcode 27 or newer. It uses a non-AR [`ARView`](https://developer.apple.com/documentation/realitykit/arview) with a [`PerspectiveCamera`](https://developer.apple.com/documentation/realitykit/perspectivecamera), an explicitly vertical field of view, and RealityKit cylinder meshes with line-fill materials, as in Stars. It does not use the device camera or request camera access. iOS-only rendering is conditionally compiled; the package still builds and tests on macOS 14.

## Coordinates and scale

`Star.galacticPositionInParsecs` computes Sun-centred Cartesian coordinates:

```
x = distance × cos(latitude) × cos(longitude)
y = distance × cos(latitude) × sin(longitude)
z = distance × sin(latitude)
```

Angles are converted to radians. RealityKit coordinates are `[x, z, -y]`, with Y pointing north and one world unit representing one parsec. Positions stay close to the Sun to preserve floating-point precision for nearby stars.

The schematic Galactic centre lies at `[8178, -20.8, 0]` in scene coordinates: positive Galactic X points from the Sun toward longitude 0°. This corrects the direction of the translated Galactic centre in the source prototype. The source's approximate context dimensions are retained: disk radius 13,400 pc, thin disk height 335 pc, thick disk height 2,600 pc.

## Rendering and lifecycle

`StarMapView` owns its `StarMapScene` through a representable coordinator. Catalogue loading has progress, failure, and retry states. Entities and sphere meshes are created once per scene. Frame updates handle camera interpolation and marker sizing; the subscription captures the scene weakly and is cancelled while hidden, inactive, showing details, or dismantled.

Constant screen size uses depth along the camera axis rather than Euclidean distance, avoiding oversized off-axis markers. Markers behind the near plane are hidden. The Sun keeps a visible screen size in both modes. Selecting a star uses the nearest projected catalogue marker within 22 points; dense overlaps are best resolved in the catalogue.
